# VERDICT — Experiment Code

Source code, experiment scripts and results for the paper:

> Bilel Zaghdoudi and Maria Potop-Butucaru. **A Verifiable Framework for Secure Data Lineage in Decentralized DAGs.** Submitted to PVLDB Vol. 20 (VLDB 2027).

VERDICT represents data lineage as two interconnected DAGs (a **Data DAG** of artifacts and an **Event DAG** of transformations). It partitions each DAG into levels and hashes every level with an **Elliptic Curve Multiset Hash (ECMH)**. It links the levels with a **deterministic binary skip DAG** that gives each element one signed path proof of logarithmic length, and it proves element membership inside a level with **bucket-indexed Merkle trees**.

All datasets are **synthetic** and are generated by the code itself, so no external data download is needed. The results used in the paper are included in `results/` and `figures/`.

## Paper-to-code mapping

| Paper | Code |
|---|---|
| §2.2 Dual-DAG model | `DataDAG`, `EventDAG`, `generate_data_dag`, `extract_event_dag` |
| §3.1 Level partitioning | `partition_into_levels` |
| §3.2 ECMH level hashing (P-256, RFC 9380 hash-to-curve) | `ecmh.py` (`ECMH`, `hash_to_curve`), `HashedLevelDAG` |
| §3.3 Signed level hashes, concatenated hashes CH(L_i) | `HashedLevelDAG.level_sigs`, `HashedLevelDAG.ch` |
| §4.1 Deterministic binary skip DAG | `SkipDAG` |
| Algorithm 1 – BinaryDescentPath | `binary_descent_path` |
| Path hash PH(π) and signed path SP(x) | `path_hash`, `sign_element_path` |
| Algorithm 2 – InsertIntoSkipDAG | `Verdict.insert` |
| Algorithm 3 – VerifyExistence (phases 1–2 / phase 3) | `reconstruct_path`, `Verdict.verify_path` / `Verdict.verify_membership` |
| §5.1 Hash-based bucket indexing | `bucket_index`, `bucket_leaf` |
| §5.2 Bucket Merkle tree, signed root, updates | `LevelMerkle` (Algorithm 4: `LevelMerkle.build`) |
| §5.3 Merkle membership verification | `verify_merkle_membership` |
| §5.4 Cross-DAG consistency verification | `link_producing_events`, `verify_cross_dag` |

Signatures use Ed25519 (the paper only requires an EUF-CMA-secure scheme). The ECMH implementation passes the official RFC 9380 test vectors for the suite `P256_XMD:SHA-256_SSWU_RO_` (see `tests/test_ecmh.py`).

## Repository layout

| Path | Purpose |
|---|---|
| `ecmh.py` | P-256 arithmetic, RFC 9380 hash-to-curve and the ECMH multiset hash. |
| `secure_lineage_system.py` | VERDICT core (all components above). Runnable end-to-end demo. |
| `lineage_system_base.py` | Writes interactive HTML visualizations of the DAGs and skip DAGs. |
| `evaluate_secure_lineage.py` | Benchmark for one configuration. Appends one row per run to `evaluation_log.csv`. |
| `evaluate_skip_insertion.py` | Benchmark of InsertIntoSkipDAG (Algorithm 2). |
| `run_experiments.py` | Runs all parameter sweeps of the paper's evaluation. |
| `plot_results.py` | Builds the evaluation figures (vector PDF and PNG; mean with 95% confidence intervals) from the CSV results. Uses LaTeX with the paper's Libertine font when available, otherwise a serif fallback (`--no-tex`). |
| `tests/` | Correctness tests: RFC 9380 vectors, ECMH properties, skip DAG structure and path bound, verification of genuine elements, and rejection of tampered, forged or inconsistent ones. |
| `results/`, `figures/` | Raw results and figures used in the paper. |

## Requirements

- Python 3.10 or newer (tested with Python 3.10.11)
- Packages in `requirements.txt`

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Quick start (about 1 minute)

```bash
# 1. Correctness tests
python tests/test_ecmh.py
python tests/test_verification.py

# 2. End-to-end demo on a small DAG
python secure_lineage_system.py --nodes 60 --genesis 4 --edges 3 --seed 1

# 3. Smoke run of all experiments, then plot them
python run_experiments.py --quick --out results_quick
python plot_results.py --results results_quick --figures figures_quick
```

The demo should end with `--> FULL VERIFICATION: SUCCESS`.

## Reproducing the paper's evaluation (Section 7)

```bash
python run_experiments.py --out results      # all sweeps, 32 repetitions each, seed 42
python plot_results.py --results results --figures figures
```

`run_experiments.py` accepts `--only nodes genesis edges insertion` to run a subset, `--runs N` to change the number of repetitions, `--max-nodes N` to skip the largest graphs, `--buckets K` (default 4) and `--seed S` (default 42).

### Parameter sweeps

| Experiment | Varied parameter | Fixed parameters |
|---|---|---|
| `nodes` | nodes ∈ {1000, 2500, 5000, 7500, 10000, 15000, 20000} | genesis = 50, max edges/node = 10 |
| `genesis` | genesis ∈ {50, 100, 200, 300, 400, 500} | nodes = 2000, max edges/node = 10 |
| `edges` | max edges/node ∈ {10, 15, 20, 25} | nodes = 1000, genesis = 50 |
| `insertion` | nodes ∈ {1000, …, 20000}, 32 insertions each | genesis = 50, max edges/node = 10 |

### What each figure measures

| Paper figure | Output file | Experiment | Measured operation (CSV column, `*` = `data` or `event`) |
|---|---|---|---|
| Fig. 1 – Skip DAG diversity vs. skip edges | `fig1_skip_diversity_vs_skip_edges.png` | `nodes` | Shannon entropy of skip-edge lengths (`*_skip_diversity`) |
| Fig. 2 – Skip DAG construction time vs. nodes | `fig2_skip_construction_vs_nodes.png` | `nodes` | ECMH level hashing + signed level hashes + skip edges, per DAG (`*_skip_dag_time_ms`) |
| Fig. 3 – Skip insertion time vs. nodes | `fig3_skip_insertion_vs_nodes.png` | `insertion` | Algorithm 2: ECMH update, binary-descent path, signed path hash (`insertion_time_ms`) |
| Fig. 4 – Skip search time vs. skip edges | `fig4_skip_search_vs_skip_edges.png` | `nodes` | Path reconstruction from L₁ to a target level (`avg_*_skip_search_time_ms`) |
| Fig. 5 – Skip DAG verification time vs. nodes | `fig5_skip_verification_vs_nodes.png` | `nodes` | Algorithm 3, phases 1–2 (`*_verification_time_ms`) |
| Fig. 6 – Bucket Merkle construction time vs. nodes | `fig6_merkle_construction_vs_nodes.png` | `nodes` | Buckets, Merkle trees and signed roots for all levels (`*_merkle_time_ms`) |
| Fig. 7 – Merkle verification time vs. nodes | `fig7_merkle_verification_vs_nodes.png` | `nodes` | Algorithm 3, phase 3 (`*_merkle_verification_time_ms`) |
| Fig. 8 – Verification time vs. genesis nodes | `fig8_verification_vs_genesis.png` | `genesis` | Algorithm 3, phases 1–2 (`*_verification_time_ms`) |
| Fig. 9 – Verification time vs. edges per node | `fig9_verification_vs_edges.png` | `edges` | Algorithm 3, phases 1–2 (`*_verification_time_ms`) |

Table 1 (comparison with LineageChain and ForensiBlock) reports figures taken from those systems' publications and is not produced by this code.

Each run also records full verification (`data_full_verification_time_ms`), cross-DAG verification (`cross_dag_verification_time_ms`), path-signing time for all elements (`*_path_signing_time_ms`), the longest measured path (`*_max_path_length`) and correctness counters (`*_signature_failures`, `*_merkle_verification_failures`, `data_full_verification_failures`, `cross_dag_verification_failures`, `*_path_bound_violations`). All counters must be 0.

### Expected running time

One run takes about 3 s at 1,000 nodes, 18 s at 5,000 nodes and about 75 s at 20,000 nodes on a recent laptop. Most of the time goes into ECMH hashing of the Event DAG, which has about 5× more nodes than the Data DAG. The full sweep with 32 repetitions takes about 3 hours. Use `--runs` and `--max-nodes` for a shorter run, for example:

```bash
python run_experiments.py --runs 5 --max-nodes 5000 --out results_short
```

Absolute times depend on the machine and Python version. The results in `results/` were produced with `python run_experiments.py --out results` (seed 42) on an Intel Core i7-12650H laptop with 64 GB RAM, Windows 11, Python 3.10.11.

## Visualizing a DAG

```bash

```

This writes `data_dag.html`, `event_dag.html`, `data_skip_dag.html` and `event_skip_dag.html`, which can be opened in a browser.
